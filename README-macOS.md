# NÜVEL Studio — macOS Apple Silicon

## แอปพร้อมใช้และอัปเดตในแอป

ดาวน์โหลด **NUVEL-Studio-macOS-arm64.zip** จาก Releases ของ repo ส่วนตัว
แตก ZIP แล้วย้าย **NÜVEL Studio.app** ไปยังโฟลเดอร์ที่คุณมีสิทธิ์เขียน
เปิดแอปได้เลยโดยไม่ต้องติดตั้ง Python หรือ Homebrew

อัปเดตผ่าน **Settings → App updates** ได้ สำหรับ repo ส่วนตัวตั้ง fine-grained
GitHub token ที่อ่าน Contents ของ repo นี้ได้ในครั้งแรก แอปเก็บ token ใน macOS Keychain
แอปยังลงนามแบบ ad-hoc และยังไม่ notarized จึงอาจมีข้อความตรวจสอบจาก macOS ตอนเปิดครั้งแรก
รายละเอียดการออก release อยู่ใน [README.md](README.md#download-the-ready-to-use-app)

ขั้นตอนด้านล่างสำหรับผู้ที่ต้องการ build จาก source เอง

## เริ่มใช้งาน

1. ดาวน์โหลดซอร์สหรือ clone repo ลงใน Mac ให้ครบทั้งโฟลเดอร์
2. ติดตั้ง Python 3.12+ แบบ native ARM64 หรือ universal2 จาก python.org
   และเปิด `Install Certificates.command` ที่มาพร้อมตัวติดตั้งหนึ่งครั้ง
3. ดับเบิลคลิก **build_macos.command** ตัว build เตรียม environment และส่วนประกอบให้เอง
4. เมื่อสำเร็จ Finder จะเลือก **NÜVEL Studio.app** ในโฟลเดอร์โปรเจกต์ให้ เปิดแอปนี้ได้เลย

เปิดใช้งานปกติโดยไม่มี Terminal ไม่ต้องเปิด `start_macos.command`
ตัวแอปรวม Python, WebKit bridge, yt-dlp, UI, โลโก้ และ FFmpeg ARM64
สามารถนำ `.app` ไปไว้ใน Applications ได้ ส่วน ZIP สำหรับแจกจ่ายอยู่ใน `dist/<เวลาที่ build>`

## อัปเดต

ปิดแอปและรอให้งานดาวน์โหลดจบ แล้วดับเบิลคลิก **update_macos.command**
ตัวอัปเดตดึงโค้ด ติดตั้งส่วนประกอบ build และตรวจแอปให้ครบในขั้นตอนเดียว ไม่มีตัวเลือก 1/2
จากนั้นเปิด **NÜVEL Studio.app** ในโฟลเดอร์โปรเจกต์ตำแหน่งเดิมได้เลย
ถ้าคัดลอกแอปไป Applications เอง ให้นำตัวใหม่ไปแทนสำเนานั้นด้วย

การอัปเดตต้องใช้โฟลเดอร์ที่ clone ด้วย Git และบัญชี Git ที่เข้าถึง private repo ได้
ไฟล์ที่แก้ไขค้างอยู่และ history ที่ไม่ตรงกันจะไม่ถูกลบทิ้งเพื่อบังคับอัปเดต

ตัวเริ่มอัปเดต `update_bootstrap.py` แยกจากตัว build และไม่เรียกใช้ updater รุ่นเก่า
ก่อนดึงโค้ดใหม่ หาก URL หลักมีปัญหาจะลอง URL อีกชื่อหนึ่งของ repo นี้ด้วยวิธีเชื่อมต่อเดิม
แล้วตรวจว่า Git อัปเกรดต่อจากประวัติเดิมได้ก่อนเรียกตัว build ที่เพิ่งอัปเดต
จึงกู้กรณีตัวประสานงาน build รุ่นเดิมเสียได้ โดยไม่รันสคริปต์จาก URL โดยตรง
ยังต้องมีอินเทอร์เน็ตและสิทธิ์เข้าถึง repo และต้องได้รับตัวเริ่มอัปเดตรุ่นนี้ก่อน
updater รุ่นเก่าที่หยุดก่อน fetch ยังต้องแก้การเชื่อมต่อหนึ่งครั้งเพื่อรับแพตช์

## ถอนการติดตั้ง

เปิด **Settings → Uninstall → Uninstall app** แล้วยืนยัน แอปจะปิดก่อนย้ายตัวเองไปถังขยะ
ทำงานออฟไลน์และใช้ Python ที่รวมมาในแอป สำหรับโฟลเดอร์ซอร์สให้ดับเบิลคลิก
**uninstall_macos.command** เพื่อถอนแอปที่อยู่ในโฟลเดอร์โปรเจกต์นั้นได้เช่นกัน

ค่าเริ่มต้นเก็บการตั้งค่าไว้ เลือกช่องลบการตั้งค่าเพื่อเอา preferences บันทึกการเปิดแอป
และ GitHub release token ของแอปออกด้วย ไฟล์สื่อที่ดาวน์โหลด ซอร์สโค้ด environment
และ build สำรองยังอยู่ หากพบโฟลเดอร์ดาวน์โหลดหรือไฟล์เพิ่มภายในแอปจะหยุดให้ย้ายออกก่อน
ปิดแอปสำเนาอื่นและรอให้การดาวน์โหลดหรืออัปเดตจบก่อนเริ่มถอนการติดตั้ง
ถ้ามีแอปหลายสำเนา เช่น ใน Applications และในโฟลเดอร์โปรเจกต์ จะถอนเฉพาะสำเนาที่สั่ง

## การตรวจแอปก่อนส่งมอบ

ทุก build จะคัดลอก bundle โดยรักษา framework symlink แล้วเปิดผ่าน macOS LaunchServices
เหมือนการเปิดจาก Finder ตรวจ UI, การเชื่อมต่อ Python และ FFmpeg พร้อมปิดหน้าต่างทดสอบ
ต้องได้รับผลยืนยันจากแอปที่เพิ่ง build จริง จึงสร้าง ZIP และแทนที่แอปหลัก
หากไม่ผ่าน จะไม่แจ้งว่า build สำเร็จและเก็บแอปเดิมไว้
แอปรุ่นก่อนจะเก็บสำรองใน `dist` ไม่ลบไฟล์ดาวน์โหลดหรือการตั้งค่า
รุ่น 2.0 ใช้ bundle ID, product ID และชื่อแพ็กเกจใหม่ทั้งหมด
ต้องติดตั้งแพ็กเกจใหม่นี้หนึ่งครั้ง แล้วตั้งค่าการเข้าถึง GitHub อีกครั้ง
ตัว build ตรวจรับแอป NÜVEL รุ่น 1.1.2–1.x ที่ยังใช้รหัสเดิมเพื่อย้ายให้อัตโนมัติ
โดยตรวจ build marker ชื่อ เวอร์ชันและไฟล์โปรแกรมให้ตรงกัน และสำรองแอปเดิมก่อนแทนที่
bundle ของโปรแกรมอื่นยังถูกปฏิเสธ

## ข้อมูลเพิ่มเติม

- MP4 บน Mac ใช้ H.264 8-bit 4:2:0 และ AAC เพื่อใช้กับ QuickTime
  stream ที่เข้ากันอยู่แล้วจะไม่บีบอัดซ้ำ ส่วนที่แปลงอาจใช้เวลาและเสียคุณภาพเล็กน้อย
- แอปรวม gallery-dl CLI สำหรับภาพจากโพสต์/อัลบั้มเป็นโปรเซสแยกไปด้วยแล้ว
  ไม่ต้องติดตั้ง CLI เอง ลิงก์ไฟล์ภาพโดยตรงใช้ตัวดาวน์โหลดในแอป
- แต่ละเว็บอาจต้องล็อกอินหรือใช้ cookies ตามสิทธิ์ของบัญชี
  สถานะรองรับหมายถึงมี extractor ไม่รับประกันทุก URL หรือการข้าม DRM
- Build ต้องทำบน Apple Silicon Mac ไม่ใช้ Rosetta ตัวติดตั้งตรวจสถาปัตยกรรมให้
- แอปที่ build ในเครื่องใช้ ad-hoc signing ยังไม่ใช่รุ่นที่ notarize สำหรับแจกจ่ายสาธารณะ
- การแพ็กและการทดสอบ LaunchServices ต้องตรวจบน Mac จริง เครื่องพัฒนา Windows ทำแทนไม่ได้

`install_macos.command` และ `start_macos.command` เป็นเครื่องมือพัฒนาสำหรับรันซอร์ส
การใช้งานทั่วไปใช้ build แล้วเปิด `.app` ตามขั้นตอนด้านบน
